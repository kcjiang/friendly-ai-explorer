# 工作台

入口 `/workbench` 位于 Dashboard 下方。标题、容器、工具栏换行遵循数据维护页面，控件使用官方 shadcn base-nova / Base UI。左侧查看周期为“今天、本周、此月”（默认本周，此月为最近30天），右侧依次为刷新、邮箱、检查更新、定时任务、AI 实时输出，自然换行。

“检查更新”将立即提交一轮收取，不要求启用定时任务，也不受工作时段限制。手动和定时收取使用 `workbench_checks` 持久化队列，按入队顺序串行执行；同一用户已有手动检查排队或执行时，重复点击直接返回原任务。定时检查不会重复加入该用户正在等待或执行的收取。每轮先同步全部邮箱，再按托管卡片顺序检查平台；相邻邮箱、平台动作以及两轮检查之间至少间隔5秒。后台进程断开后会恢复未完成记录，失败不阻塞后续队列，完成记录保留30天。自动化处理仍独立执行。

## 部署

开发和生产部署统一使用 `db/init.sql` 初始化空库；工作台 worker 使用与 API 相同的数据库和根密钥。表名统一采用 `workbench_*`，没有运行时迁移和旧抓取指纹表。

平台使用 HTTPS，邮箱使用 SSL/TLS 或 STARTTLS，并保持证书校验。平台和邮箱凭据使用独立的 HKDF-SHA256 派生密钥，通过 Fernet 加密保存；不兼容旧密文。部署前配置新的高强度 `APP_MASTER_KEY`，之后保持稳定。

邮箱需启用 IMAP/SMTP，并按服务商要求使用密码或应用专用密码；支持 SSL/TLS 和 STARTTLS，校验证书。尚未接入 OAuth。Jira 使用已有 REST 认证客户端获取问题和评论；YouTrack 使用永久访问令牌。仅从配置根站点中的问题链接收取详情，不跟随任意邮件网址发送平台凭据。

## 邮箱客户端

先配置邮箱，再创建托管任务。邮箱为非模态浮窗，每次打开居中，无背景模糊，支持标题拖动、八方向边框缩放和最大化/还原。支持多个邮箱和全部远程文件夹。没有邮箱账户时，由用户点击“登录邮箱”或“添加邮箱”打开设置；轮询不打开弹窗，也不重置正在输入的配置。

同步只读取服务器收件时间 INTERNALDATE 在最近30天内的邮件，每页30封，可搜索主题。界面显示后台同步状态及失败原因。分类规则设置发件人邮箱/域名、主题关键词、目标文件夹：发件人与主题条件同时满足，多个主题关键词匹配其一即可；多条规则采用第一条命中规则。规则移动服务器原邮件，创建文件夹也写入原邮箱。

顶部邮箱按钮显示所有已配置邮箱的未读数量，同一 Message-ID 的文件夹副本只计一次，零未读不显示气泡。页面每8秒刷新计数，打开原文后立即更新。搜索栏固定在邮箱菜单右侧；宽屏采用官方 shadcn Resizable withHandle，侧栏160–320px且不超过窗口40%，主区至少360px；窄屏恢复文件夹下拉框。

同步使用只读 SELECT、BODY.PEEK[]，不标记邮件已读。分类优先 IMAP MOVE，兼容分支要求 UIDPLUS，使用定向 UID EXPUNGE，绝不全邮箱 EXPUNGE。只有用户打开原文才同步服务器 `\Seen`，其他客户端的读标记在同步时更新回来。工作台信息已读与邮箱已读独立。已分类邮件通过颜色和标记区分。

支持回复、转发、收件人/抄送/密送、附件和 HTML 富文本。Tiptap 配合 shadcn 工具栏提供字体、颜色、粗斜体、下划线、列表、对齐、链接、图片和撤销重做；SMTP 生成纯文本及 HTML MIME，密送只放入 SMTP 信封。草稿仅保留在当前窗口会话，没有服务端草稿箱或定时发送。

发送使用一次性请求 UUID，发送前持久化状态；结果不确定时禁止同一请求自动重发，提示先到原邮箱确认。成功发送但已发送副本保存失败时单独提示，不能重发整封邮件。收件人和主题为同行输入，抄送/密送默认折叠；超链接保存选区，支持无选区插入、修改显示文字/网址以及移除链接。

HTML 阅读保留安全样式表、媒体查询、表格、字体、颜色和内嵌图片。CSS 通过 tinycss2 与 bleach CSSSanitizer 清理，过滤脚本、事件、嵌入对象、CSS网络请求等主动内容；正文在无脚本沙箱 iframe 中显示。外部图片默认不载入，用户可对当前邮件点击“显示外部图片”。正文及窗口滚轮在顶部/底部不会穿透到工作台，支持 CID 图片和附件下载。

单封收取上限10MB，单附件或正文图片5MB，发送总大小15MB；每轮最多10000封和200MB原文，超限报错不静默截断。协议有网络超时和同步总时限；完整同步失败保留已有缓存。

## 托管和状态

创建托管任务填写客户名称、项目库项目、平台、根网址、用户名/密码、链接邮件文件夹，以文件夹取代查询条件。现有账号保留加密凭据，但需补充项目和文件夹才继续收取。旧缓存继续保留，新通知优先关联已有同一问题卡片。

仅关联文件夹内最近30天的通知触发网站收取。同一问题汇总为稳定卡片，关联每封仍在该文件夹和保留期内的邮件；点击关联邮件打开邮箱原文。邮件内问题链接优先与主题编号匹配，避免误用相关问题链接。

按邮件收件时间与信息的资源更新时间比较，仅更晚的通知触发网站详情更新。Jira/YouTrack 返回的更新时间也参与比较；没有可信源时间时使用邮件时间，不使用抓取时的本地时间。记录最新触发来源及邮件链接，旧邮件补入文件夹只补关联，不重复更新或改变处理状态。每个托管任务内按各问题最新通知的时间从旧到新收取。

创建工单沿用信息绑定的托管项目，不再单独配置目标项目。信息创建时固定项目，自动化入队时保存项目快照，后续修改托管项目不会改变已有信息和任务的去向。

托管平台与自动化卡片支持确认删除。删除配置立即隐藏并停止接收新任务，已入队自动化继续完成，处理记录沿原缓存期限保留，已创建的 Ticket 不变；删除配置超过30天且无关联缓存/任务后清理。

工作面板使用 shadcn 线样式 Tabs：

| 状态 | 收到新通知 | 自动化与读取 |
| --- | --- | --- |
| 待处理 | 更新原卡片、标记未读 | 打开信息仅工作台已读；分配自动化立即移入已处理 |
| 已处理 | 无运行任务时移回待处理；执行中先积累更新，结束后再移回 | 查看步骤、阶段、结果和历史；失败留在已处理并允许重试 |
| 已忽略 | 保留在已忽略、标记未读 | 可查看和恢复；恢复后才能提交自动化 |

自动化失败后收到更新且没有运行任务时也回到待处理，保留失败记录。重试沿用旧输入和已完成检查点，按规则重排队尾；已完成步骤前缀不得修改后重放。Ticket 写入和步骤检查点在同一事务提交，避免重复建单。信息详情每4秒刷新阶段，内嵌处理记录每页10次；自动化执行记录每页30条。详情返回记录时省略重复的输入正文，完整输入仍保存在任务快照中。

## 调度、缓存和布局

计划初次读取浏览器 IANA 时区，后续用户主动调整。默认周一至周五09:00–18:00，每1小时收取，支持自定义工作日、起止时间、15/30/60/120/180/240分钟间隔。不使用日期例外。从开始时间依次计算，仅判断开始时是否在工作时段，已开始的不取消；不补跑下班时段。UTC 存储执行时刻，处理夏令时。

后台每15秒检查收取计划，先完成全部邮箱同步，再按托管卡片顺序从上往下收取来源。邮箱“收取全部”使用相同流程，手动收取不受定时时段限制。API 与 worker 通过用户级会话 advisory lock 互斥，锁由专用连接持有，跨逐条提交仍然有效；连续点击在同一 API 进程内也只创建一个任务。每个问题独立提交，失败保留其他成功结果并继续后续问题。自动化独立运行，按卡片顺序轮询，同一卡片内先进先出；失败不阻塞其他任务。重试按信息→任务顺序加锁，与资源更新一致。

缓存清理由独立60秒循环执行，长时间收取不阻塞清理。原始 AI 调试输出采用滚动窗口，每用户最多512块、每块最多16000字符，同时遵守30天到期；接口单次最多200000字符，前端同样只保留最近200000字符。单个 AI 步骤输出超过100000字符时失败并提供重试，防止无限输出占用内存。有效托管/自动化配置各最多200个，与排序接口上限一致。已不存在且无配置引用的邮件文件夹缓存会自动清理。

前端 `use-polling.ts` 统一串行轮询：上一次完成后才安排下一次，取消过期请求，后台标签页暂停轮询。邮箱浮窗打开时暂停页面重复的邮箱轮询；快速切换文件夹/搜索时旧响应不覆盖新列表。邮件列表只查询元数据，不加载原始 MIME 或正文；同步时每封缓存邮件只加载一次，文件夹副本共用缓存对象。草稿固定发件邮箱，打开关联邮件不会静默丢弃未发送的草稿。

- 邮件按收件时间+30天到期；移动文件夹、重复收取、打开均不续期。只清理本平台缓存，不删除服务器邮件。
- 信息卡片按最新关联邮件收件时间+30天到期，新邮件才延长。人工补充、步骤、失败记录随卡片到期，重试或任务完成不额外延长。
- 已忽略信息30天内保留状态，全部过期后忘记；旧邮件仍在服务器但不满足时间范围，不会重新抓回。未来新邮件可作为新信息进入待处理。
- 排队/执行输入暂存到任务结束，过期信息不显示，结束后按原期限清理，避免中断已接受的任务。
- Ticket 独立永久保存，缓存清理不删除 Ticket。账号、规则、托管设置属于长期配置。
- 通过 30 天内的邮件标识和问题关联去重；不永久保存忽略状态。每个任务最多保留最近 200 条步骤和重试日志。
- 查看周期和未读数量受30天限制。工作面板按时间从旧到新显示，每页30条，底部翻页；切换周期、平台、状态回到第一页。信息不支持手动排序，仍可拖入自动化；平台和自动化保留拖动排序，卡片及拖动预览统一箭头光标。卡片、按钮和确认框沿用官方 shadcn base-nova，拖动由 dnd-kit 提供（shadcn 无通用拖动排序组件）。

工作区按容器宽度切换：960px以上三栏、640–959px顶部平台栏和下方双栏、更窄时切换工作面板和自动化，栏目跟随整页滚动。邮箱按窗口宽度切换文件夹侧栏与下拉选择，正文滚动，标题、菜单和发送按钮固定。设置弹窗采用固定标题、正文滚动、固定操作栏，仅叉号关闭。

## 模块与命名

后端采用 Python snake_case，按 routers / schemas / models / services 分层。`workbench_collection.py` 集中收取顺序、用户互斥、邮件触发与逐条资源更新；`workbench_resources.py` 负责 HTTPS 地址格式校验和标准内容结构；`workbench_limits.py` 统一缓存及容量常量。协议、邮件缓存、HTML 清理和调度时间计算分别保留独立模块。

前端组件与 hooks 使用 kebab-case 文件名，shadcn 官方组件保留在 `components/ui/base`，工作台业务组件放在 `components/workbench`，通用轮询放在 `hooks/use-polling.ts`。移除了旧的整站抓取/独立 IMAP 入口；旧缓存测试生成器放在 `tests/workbench_fixtures.py`，不会再进入生产收取流程。数据库表名保留以避免不必要的数据迁移，原有兼容缓存按到期时间清理。

AI 实时输出保留独立非模态浮窗，显示连续纯文本及执行标记，不暴露内部推理通道。约200ms分批记录，前端按游标读取，窗口保留最近20万字符，调试事件30天清理；关闭窗口不影响执行。

## 验证

```sh
docker compose exec -T backend python -m unittest tests.test_workbench tests.test_workbench_mail -v
docker compose exec -e WORKBENCH_WORKER_TEST=1 -T backend python -m unittest tests.test_workbench_worker -v
docker compose exec -T frontend node node_modules/typescript/bin/tsc --noEmit --incremental false
docker compose exec -T frontend node --test tests/floating-window.test.cjs
```

数据库测试使用事务回滚；远程收发使用 mock，不发送真实邮件。覆盖分类不标记已读、显式打开同步读标记、INTERNALDATE、移动不续期、失败保留缓存、30天清理、执行中更新、忽略与恢复、发送防重、用户隔离及原有工作台功能。真实邮箱联调需配置服务器和授权信息。
