# 知识库问答与索引

## 本次修复

Google 的 `text-embedding-004` 已在 2026-01-14 停用，继续调用会得到 NotFound。[Google 官方生命周期说明](https://ai.google.dev/gemini-api/docs/deprecations#embedding-models)

向量服务在管理后台 → AI 服务与调度 → 知识库向量服务独立配置，支持 Gemini 原生、OpenAI 兼容 `/embeddings` 及“仅关键词检索”。首次未配置时仅使用关键词检索，不自动选择模型或读取供应商环境密钥；保存后使用数据库配置，不随聊天模型切换。独立密钥加密保存，查询不返回明文。

维度固定为 768，进行有限值、维度校验和归一化，不改变现有 `vector(768)` 列。Gemini 查询使用 `retrieval_query`，文档使用 `retrieval_document`；OpenAI 兼容接口可分别配置查询和文档前缀。更换模型、接口地址或前缀后必须重新生成文档向量；维度相同也不能混用不同编码器的向量空间，服务临时失败时不自动切换到不同向量模型。

文档保存时先后端生成文本块，即使向量 API 超时、限流或无权访问，也会保存文本索引。新向量在块的 metadata 中记录模型及维度标识，查询只使用与当前配置匹配的向量。旧未标记向量不会参与新模型的相似度排序。

检索组合关键词与向量结果，支持中英文、产品型号。向量故障时仍搜索知识库；对历史“文档已保存、索引块为零”的数据，也会检索保存的正文片段。只有已发布且当前用户可见的文档会参与聊天和工单分析，私有文档仅作者可检索，草稿不参与。

聊天优先参考知识库，没有相关资料或资料不足时调用当前选定的聊天模型进行通用问答。提示词要求区分通用知识和内部记载，不编造内部产品参数、项目状态或客户信息。每次检索日志包含模式（hybrid/keyword/vector/none）、命中数、文档 ID 和向量模型，不记录完整文档、问题或密钥。

标题和正文都属于事实依据。后端附上实际检索到的“知识库参考资料”，不依赖模型编造引用；该列表表示检索结果，不意味着通用回答中的每一句都来自这些文档。聊天支持最近最多 5 轮完整对话，失败回复不进入下一轮上下文，可点击“开始新对话”清空。

聊天同时接收当前页面类型（工作台、工单、知识库、邮件、调试、资料库、管理后台），用于提供相关建议。不发送页面 DOM、表单或业务详情；当前没有执行工具，不能读写当前页面记录。后续智能体应通过服务器鉴权后的工具调用读取业务数据，并将写操作设计为可审核的操作流程。

## 使用方法

1. 在知识库创建或编辑文档，写入产品型号、名称和具体事实，勾选发布。只有标题而正文为空的文档不能建立内容索引。
2. 保存后查看索引状态：“文本与向量索引就绪”表示可以进行混合检索；“文本可检索，向量暂不可用”仍可使用产品型号/名称查询。
3. 旧文档、切换向量模型后的文档，由作者点击列表或详情页的“重建索引”。重复重建会替换旧块，不会追加重复记录，也不修改文档正文。
4. 询问具体型号，例如“S905 是哪个公司生产的芯片？”，再在管理后台应用日志中按当前请求编号查询“RAG 知识库检索完成”。

“待重建索引”表示无文本块，系统仍可回查非空原文；“草稿”不参与问答；“正文为空”需先补充内容。索引重建权限与编辑权限一致，仅作者可操作。重新编辑期间，较早的索引任务不会覆盖更新后的正文版本。

## 部署

当前版本仅支持全新数据库部署，开发和生产 Compose 都只执行 `db/init.sql`。旧数据库与旧密文不兼容，请按 [数据库重建](database-reset.md) 准备空库后部署。

## 本地模型接入示例

聊天模型和 Embedding 模型是两类服务；现有 Qwen 聊天服务不能直接用于向量化。可在独立的本地 Embedding 服务中运行 `BAAI/bge-base-zh-v1.5`（原生 768 维），由支持该模型的 vLLM 版本提供 OpenAI 兼容接口，或经 New API 网关转发 `/v1/embeddings`。在 DGX Spark 上须使用适配其 ARM64 / GPU 架构的运行环境，不能直接照搬 x86 镜像。

管理后台填写：

```text
接口类型：OpenAI 兼容 Embeddings
API Base URL：http://向量服务地址:端口/v1
模型：网关实际暴露的 Embedding 模型名
API Key：网关密钥（无认证的内网服务可留空）
查询前缀：为这个句子生成表示以用于检索相关文章：
文档前缀：（留空）
请求 dimensions=768：原生 768 维 BGE 模型通常不需要；仅在接口支持时勾选
```

先保存并测试，再由文档作者重建已发布文档的索引。测试会分别检查查询和文档向量，不返回原始向量。若使用其他模型，按其文档设置前缀与输出维度；1024 / 384 维输出会被明确拒绝，不做截断或补零。接口不可用时可以选择“仅关键词检索”，以避免依赖 Google。

最低向量相似度默认 0.65，可按模型和真实问题调整（0–1）。门槛过低容易把无关资料当作参考，过高会漏掉语义相关资料；调整门槛不需要重建索引。

参考：[BGE 中文模型说明及维度](https://huggingface.co/BAAI/bge-base-zh-v1.5)、[vLLM Embedding 模型与接口](https://docs.vllm.ai/en/stable/models/pooling_models/)。

聊天路由保持管理后台所选服务，向量模型独立于 Gemini/Qwen 聊天模型。选择本地聊天模型不会使已配置的 Google 向量服务变成本地向量服务。
