# 知识库问答与索引

## 本次修复

Google 的 `text-embedding-004` 已在 2026-01-14 停用，继续调用会得到 NotFound。[Google 官方生命周期说明](https://ai.google.dev/gemini-api/docs/deprecations#embedding-models)

默认向量模型改为仍可用的 `gemini-embedding-001`，显式请求 768 维，并进行有限值、维度校验和归一化，不改变现有 `vector(768)` 列。通过 `EMBEDDING_MODEL` 可配置模型，密钥仍使用后端 `GOOGLE_API_KEY`。查询使用 `retrieval_query`，文档使用 `retrieval_document`。更换模型后必须重新生成文档向量；维度相同也不能混用不同模型的向量空间。

文档保存时先后端生成文本块，即使向量 API 超时、限流或无权访问，也会保存文本索引。新向量在块的 metadata 中记录模型及维度标识，查询只使用与当前配置匹配的向量。旧未标记向量不会参与新模型的相似度排序。

检索组合关键词与向量结果，支持中英文、产品型号。向量故障时仍搜索知识库；对历史“文档已保存、索引块为零”的数据，也会检索保存的正文片段。只有已发布且当前用户可见的文档会参与聊天和工单分析，私有文档仅作者可检索，草稿不参与。

没有相关资料时，聊天直接说明未找到，不调用模型凭空生成产品信息。检索资料作为内部产品事实依据传给当前选定的聊天模型。每次检索日志包含模式（hybrid/keyword/vector/none）、命中数、文档 ID 和向量模型，不记录完整文档、问题或密钥。

标题和正文都属于事实依据。若小模型在已命中资料时仍泛化回答“知识库未提供相关信息”，系统改为显示命中的原文，并在日志记录模型未能利用资料；资料来源标题由后端根据实际命中的文档附加，不依赖模型编造引用。

## 使用方法

1. 在知识库创建或编辑文档，写入产品型号、名称和具体事实，勾选发布。只有标题而正文为空的文档不能建立内容索引。
2. 保存后查看索引状态：“文本与向量索引就绪”表示可以进行混合检索；“文本可检索，向量暂不可用”仍可使用产品型号/名称查询。
3. 旧文档、切换向量模型后的文档，由作者点击列表或详情页的“重建索引”。重复重建会替换旧块，不会追加重复记录，也不修改文档正文。
4. 询问具体型号，例如“S905 是哪个公司生产的芯片？”，再在管理后台应用日志中按当前请求编号查询“RAG 知识库检索完成”。

“待重建索引”表示无文本块，系统仍可回查非空原文；“草稿”不参与问答；“正文为空”需先补充内容。索引重建权限与编辑权限一致，仅作者可操作。重新编辑期间，较早的索引任务不会覆盖更新后的正文版本。

## 部署与配置

此修复不新增数据库列或迁移。现有部署更新后端、前端及 Compose 文件后，默认使用替代模型；首次升级需为原有已发布文档重建索引。开发环境代码挂载会热更新，环境变量变化需重新创建容器。

```text
GOOGLE_API_KEY=原有 Google API 密钥
EMBEDDING_MODEL=gemini-embedding-001
```

向量请求单次最多等待 16 秒，一篇文档的在线向量构建最多等待 45 秒，超出后保留关键词索引；文档内容按 800 字符分块，逐批（最多 8 块）提交。暂不可用的服务短暂冷却，避免每个问题都重复等待失败。大量长文档的完整向量重建应安排独立后台任务；当前同步重建适用于小规模文档，关键词路径始终可用。

聊天路由保持管理后台所选服务，向量模型独立于 Gemini/Qwen 聊天模型。选择本地聊天模型不会使已配置的 Google 向量服务变成本地向量服务。
